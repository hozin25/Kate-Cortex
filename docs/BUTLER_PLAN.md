# AI 管家计划：从「对话即沉淀的知识库」升级为「越用越懂你的桌面管家」

> **状态：方向已评审拍板（2026-10-14），实施未开始。**
> 背景调研（OPPO 小布记忆）与决策记录见 §1-§3；四阶段路线图 P0-P3 见 §4-§7；
> 暂缓项见 §9。各阶段动工前按仓库惯例先细化设计再实施。

---

## 0. 一句话概述

把 Kate 的默认人设升级为**管家**：以现有记忆系统（vault md + SQLite 双写 + 三层检索 +
常驻画像）为底座，补齐 **采集 → 加工 → 巩固 → 主动服务** 四环，使其成为对标贾维斯的
桌面 AI 管家——不是记得多，而是**认知持续更新、且会主动开口**。

## 1. 背景调研：OPPO 小布记忆（2026-10-14）

### 1.1 产品内核

一句话：**捕获无处不在、整理全自动、召回靠对话、正在走向主动**。

| 机制 | 做法 |
|---|---|
| 一键闪记 | 实体按键 / 三指上滑捕获屏幕内容，能抓屏幕外信息（公众号全文、评论区），附截图与原文跳转 |
| 信息提炼 | 保存时自动生成摘要、提取日程等结构化事项、智能打标 |
| 智能合集 | 按内容关联性自动建合集归档；自建合集自动回填存量、新内容自动归入（订阅效果）；ColorOS 16 规划「魔法合集」（帮你追星/记账）——合集向 agent 演化 |
| 记忆问答 | 自然语言跨多条记忆综合回答（吉尼斯纪录「3 分钟内准确回答最多问题的 AI 手机」） |
| 隐私 | 端侧存储 + 端侧脱敏 + 隐私沙箱 |

ColorOS 16 演进方向：**记忆搜索、记忆问答、记忆推荐**三矩阵；官方另一篇主题为
「记忆，该治好 AI 的健忘症」。**记忆推荐 = 主动化**，是行业共同方向（vivo 小 v 记忆同期跟进）。

### 1.2 真实槽点（知乎 / 小众软件论坛实测反馈）

- 适配面窄：第三方浏览器、部分 App 只能存截图甚至丢链接；
- **不能手动导入、不能批量导出**——数据被锁在手机里；
- 自建合集偶尔归错；有用户实测搜索时好时坏；
- 「未来空间很大，当前作用很小」：只被动存储、不主动，是体验瓶颈的共识；
- 小众软件论坛有人问「Windows 上有没有类似的 AI+记忆软件」——**桌面端是空白**。

### 1.3 结论

小布记忆验证了「系统级个人记忆」的需求与形态，但其强项（采集）在手机端，
Kate 的强项（存储与召回：FTS+向量 RRF、importance/keywords 打分、常驻画像注入）
恰是小布的弱项。**手机端小布负责采集（传感器），桌面端 Kate 负责加工与主动服务（大脑）**。

· veryjack.com 评测 · meta.appinn.net/t/topic/77176。

## 4. P0：记忆加工流水线（导入 LLM 加工）

**目标**：导入的记忆不再是「死记忆」。现状 `importer.py` 的 import_vault/import_obsidian
原样搬运 md，导进来的条目没有 keywords/importance/合集归属，检索打分吃亏。

**范围与关键设计**：

1. 新增导入后加工步骤（`importer.py` 增 enrich 阶段或独立 `enrich.py`）：对每条
   `source=import` 且缺 keywords/importance 的条目调 LLM 生成——场景关键词（3-8 个，
   与 `skills/memory.py` save_memory 同规范）、重要度（1-5）、合集归属（从用户现有
   合集列表选择，确实无归属时建议新建）、相邻重复标记（复用向量查重）；
2. **best-effort 不阻塞导入**：LLM 失败的条目保持原样可重跑；沿用 ImportReport
   + dry_run 惯例，报告里单列「加工成功/跳过」；
3. 沿用 summarizer.py「遍历内容调 LLM 写回」的既有范式；provider 走当前配置的默认会话模型；
4. 设置页导入面板加「导入后自动加工」开关（默认开）+ 手动「补加工」入口。

**验收**：导入一批无 frontmatter 富字段的 md 后，条目自动获得 keywords/importance/合集，
search_knowledge 与 recall 能命中；重复导入的相似条目在报告中被标记。

## 5. P1：记忆巩固引擎（「越用越懂你」的核心回路）

**目标**：记忆库从「只写不改」变为自我维护。四个子机制：

1. **重复消解与合并**：批量用向量索引取相似条目对（候选对零成本），LLM 判定
   重复/新版本/矛盾/不同；新版本合并为一条（保留最新事实、keywords 并集、重要度重算）；
2. **重要度动态调整**：从既有 `messages.knowledge_refs` 列统计每条记忆的召回次数与
   最近召回时间（**无需新增埋点**）；常被召回 → importance 上调（更易进常驻 top5）；
   长期未召回 → 下调，跌破阈值退出常驻池；
3. **画像维护**：定期将新记忆与「个人信息」合集比对，新的持久事实合并进画像条目
   （如零散过敏记录 → 「过敏原：咖啡因、芒果」），过时画像事实修订；
4. **归档（可选）**：低重要度久未召回的记忆移入归档态——不再自动注入，仍可搜索。
   **降权不是删除**，vault 仍是事实源。

**混合自主度（已拍板）**：LLM 判定为明显重复 → 自动合并，原条目进 `.trash`（30 天
可恢复）+ 记入整理报告；冲突/拿不准 → 进提案队列，记忆页逐条确认。**破坏性变更
永不静默执行**。

**触发与成本**：应用启动时检查（距上次整理 >7 天且有新记忆则后台跑）+ 记忆页手动
「整理记忆」按钮；每次 LLM 调用量 = 候选对数（十几次小调用），一周一跑可忽略。

**边界**：只作用于「记忆」「个人信息」两个系统合集，**不碰知识库文档**（攻略/说明书
等资料不做自动合并）。与 P0 配套：小布存量数据导入后先跑一遍巩固，洗掉重复与演化
冲突再开始使用。

**验收**：构造「在学日语」+「N3 考过了」类演化对 → 自动合并且报告可查可撤销；
高频召回条目 importance 上升；画像条目随新事实更新；知识库文档零改动。

## 6. P2：管家人设 + 主动服务（贾维斯之魂）

**目标**：懂你且会主动开口。

1. **人设升级**：`chat/prompts.py` PERSONA 从通用助手改为管家人格（称呼、语气、
   主动串联记忆的表达方式）；工具规则不动；自定义 agent 叠加机制不变（agent 仍可
   覆盖人格，如「私人生活医生」）；
2. **晨报/简报**：启动时（或用户接受的时刻）基于记忆生成今日简报——日期型记忆到期
   （行程/缴费/复诊）、重要记忆的跟进提醒、基于合集的主动建议；生成走既有 LLM 链路；
3. **主动提醒**：Electron 主进程定时检查日期型记忆，到期经系统 Notification 推送；
   尺度保守（仅日期型 + 高重要度），避免打扰；
4. 记忆页/首页呈现简报卡片（科技感视觉在 P3 统一打磨）。

**验收**：存一条「10 月 20 日复诊」→ 20 日启动时晨报提及并可推送通知；默认人设
对话语气为管家风格且记忆沉淀等工具行为不变；医生 agent 不受影响。

---

## 7. P3：桌面一键闪记 + 科技感

1. **全局快速捕获**：Electron `globalShortcut` 注册全局热键 → 剪贴板/选中文本弹卡
   → 走 save_memory 同款管线（LLM 关键词/重要度/合集，即 P0 加工复用）→ 入库，
   复刻小布最被称道的「随手一记」体验；
2. **科技感 UI**：晨报页/记忆空间的贾维斯式视觉（终端感/全息感、状态自检动效）；
   定位是锦上添花，**科技感的本体是「主动 + 懂你」的行为**，视觉放最后。

## 8. 实施顺序

| 阶段 | 前置 | 主要涉及 | 备注 |
|---|---|---|---|
| P0 | 无 | `importer.py` · 新 enrich 模块 · 设置页导入面板 | 用户小布数据导入的前置条件 |

`cd backend && uv run pytest`、`cd frontend && pnpm typecheck && pnpm lint && pnpm test`，
并同步 DESIGN.md / README.md。

## 9. 待办（暂缓）

### 9.1 手机采集 → 电脑管家联动

Web 版已有的前提下，加移动端分享/上传入口（手机小布记忆导出 → 手机直接推给 Kate，
省去手工搬运）。

- **暂缓原因**：桌面端 P0-P3 未落地；当前「手机导出 → 电脑整理 → Obsidian 导入」
  的一次性手工迁移可接受，联动属采集端扩展，优先级低于巩固与主动层。
- **重启条件**：P3 完成后；或用户形成「手机小布定期导出」的持续工作流、手工搬运
  成本明显时提前立项。
- **最小版本**：Web 版加一个上传/粘贴入口复用导入管线（含 P0 加工），无需独立 App。
