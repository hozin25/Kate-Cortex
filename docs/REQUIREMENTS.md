# Kate-Cortex 需求文档

> 个人知识库 + AI 对话桌面应用。本地优先，对话即沉淀。
>
> 版本：v0.1-draft · 更新：2026-08-17 · 状态：需求讨论中（持续补充）

---

## 1. 产品定位

Kate-Cortex 是**本地优先的个人知识库 + AI 对话桌面应用**：

> 你和 AI 聊天讨论任何话题；聊出有价值的内容时，AI 把它总结沉淀进知识库；
> 下次再聊，AI 自动引用你沉淀过的知识，越来越懂你。

核心闭环：**对话 → 沉淀 → 引用 → 越来越懂你**

它不是通用笔记软件（不替代 Obsidian），也不是纯聊天客户端（DeepSeek 桌面端），
而是把两者拧在一起：**对话是知识的第一入口，知识是对话的记忆**。

### 1.1 相对原设计的变更（2026-08-17）

原 [DESIGN.md](./DESIGN.md)（v0.1，2026-07-27）定位为"程序员编程知识库"。本次需求变更：

| 维度 | 原设计 | 新需求 |
|---|---|---|
| 知识范围 | 编程知识特化 | **全领域通用知识**（编程、学习、阅读、生活决策……） |
| AI 对话 | v0.2 远期功能 | **MVP 核心功能**，类 DeepSeek 桌面端体验 |
| 知识入库 | 手动在桌面端填写 | **对话中自动总结入库**（对话指令 + AI 主动建议） |
| 知识引用 | 未明确 | 对话默认开启 RAG，可一键关闭 |
| 模型接入 | GLM / DeepSeek 二选一（v0.2） | DeepSeek + GLM **多家可切换**（MVP） |

> 注：DESIGN.md 的技术架构（Tauri + FastAPI + markdown/SQLite 双写）仍然成立，
> 具体设计待本需求稳定后同步更新。

## 2. 目标用户与场景

**用户**：个人单机使用。

**核心场景**（按优先级）：

1. **AI 对话**：像用 DeepSeek 桌面端一样，随时开聊任何话题
2. **对话中沉淀**：说一句「记一下」，或 AI 主动建议 → 当前讨论被总结成一条知识入库
3. **知识管理**：浏览、搜索、编辑、整理知识库
4. **知识引用**：对话时 AI 自动检索知识库，回答基于你的历史沉淀

**反场景（不做）**：

- 多人协作 / 团队共享 / 云端同步
- 通用笔记软件（不追求 Obsidian 的插件生态）
- 移动端

## 3. 功能需求（MVP）

### 3.1 AI 对话（新增，MVP 核心）

| 功能 | 描述 |
|---|---|
| 多模型切换 | DeepSeek + GLM，走 OpenAI 兼容协议统一接入，设置中切换默认模型 |
| 流式输出 | 打字机效果，回答 markdown 渲染（代码高亮、列表、表格） |
| 会话管理 | 多会话并行，历史本地保存；重命名、删除会话 |
| 多轮上下文 | 维护对话上下文，支持长对话 |
| Provider 配置 | 各家 API key 分别配置，本地存储 |

### 3.2 知识收集 skill（新增，MVP 核心）

对话中把有价值内容沉淀入库，两种触发方式：

1. **对话指令**（用户主导）
   - 用户说「记一下」「这个存入知识库」等
   - AI 识别意图 → 调用 `save_knowledge` 工具
   - 自动总结**当前话题**（非全量对话）→ 生成标题、合集建议 → 入库
   - 界面展示「已保存」卡片，可点击查看
2. **AI 主动建议**（AI 主导）
   - AI 判断对话中出现有沉淀价值的内容（结论、方法、决策、经验）
   - 主动提示「这段讨论值得存入知识库吗？」
   - **用户确认后**才写入，不自动保存

### 3.3 知识引用 RAG（新增，MVP）

- **默认开启**：每次提问先检索知识库，相关知识注入上下文，回答可溯源到条目
- 对话界面提供**一键开关**（纯闲聊时可关，省 token）
- MVP 检索：关键词（FTS5）；语义向量检索放 v0.2

### 3.4 知识库管理（保留原设计，泛化）

| 功能 | 描述 |
|---|---|
| 创建/编辑条目 | 表单（标题/合集）+ markdown 编辑器，frontmatter 自动维护 |
| 列表浏览 | 按合集过滤 + 全文搜索，默认「全部」视图 |
| 详情查看 | markdown 渲染 + 元数据展示 |
| 删除 | 软删除（`.trash/`），可恢复 |
| 合集管理 | 用户自建合集（创建/重命名/删除），多对多收录条目，唯一组织机制 |
| 双向链接 | `[[slug]]` 解析 + 反向链接展示 |

### 3.5 设置

- 模型 Provider：API key、默认模型切换
- 知识引用开关（全局默认值）
- vault 路径

## 4. 知识模型

### 4.1 合集（v2，取代固定分类）

- **无固定分类**：条目不再有 `type`（笔记/剪藏/决策/方法已移除），统一进「全部」
- **合集由用户自建**：任意名称（如「金融」「情感」「编程」），一条内容可同时
  收录进多个合集（多对多），也可不属任何合集
- **AI 可建议合集**：对话沉淀时 AI 从已有合集中建议收录（系统提示注入合集名
  列表），建议卡片上用户可增删后确认，也可全部拒绝
- **合集是唯一组织机制**（2026-08-19 v3 起）：标签已移除——标签与合集语义重叠
  且易混淆，统一由合集承担组织职责。存量条目 frontmatter 里的 tags 原样保留在
  md 文件中（不展示、不索引），`个人信息` tag 的条目由启动迁移自动转入同名合集

### 4.2 存储（沿用原设计）

- 知识条目：markdown（事实来源）+ SQLite（索引）双写，按年月归档
- **新增**：对话历史存本地 SQLite（`conversations` / `messages` 表），不出本地

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 本地优先 | 知识库 + 对话历史全本地；仅调用 LLM API 时出网 |
| 数据可读 | 知识 = 人类可读 markdown 文件，可 git、可手动编辑 |
| 服务边界 | 本地 API 绑定 `127.0.0.1`，不对外暴露 |
| 密钥安全 | API key 本地存储，不入库、不进 markdown |
| 删除安全 | 软删除保留期后清理 |

## 6. 里程碑（重排）

| 阶段 | 内容 | 预估 |
|---|---|---|
| 1 | 后端知识库骨架：db / frontmatter / storage / entries CRUD | 1 天 |
| 2 | Provider 层（DeepSeek + GLM）+ 对话 API（流式 SSE）+ 会话存储 | 1.5 天 |
| 3 | 知识收集 skill：总结入库 + 保存卡片 + AI 主动建议 | 1 天 |
| 4 | 前端：对话界面（类 DeepSeek 布局）+ 知识库界面 + 设置 | 2 天 |
| 5 | RAG 检索注入 + Tauri 桥接 + 打包 | 1 天 |

**MVP 预估：6~7 人天**（原纯知识库方案为 4 天）
